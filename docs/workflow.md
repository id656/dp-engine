# Порядок работы над объектом (автономно, от обмера и референсов до альбома)

Цель: из обмерного плана и референсов получить полный комплект рабочих чертежей бюро без промежуточных
согласований. Вопросы и конфликты собираются в один список в конце; останавливаться — только перед
необратимым решением, которое может пойти в обе стороны (снос стены неизвестной несущей способности и т. п.).

## 0. Подготовка (2 мин)
- Движок: репозиторий `id656/dp-engine` (подключить и склонировать) или приложенный архив `dp-engine.zip`
  → распаковать в `/home/claude/dp-engine`. Проверка: `python3 tools/regress.py` → «OK».
- Новый объект: `cp -r objects/_template objects/<шифр>`; удалить из копии `out/`, заполнить `project.py`.

## 1. Исходные данные → obmer.py
- Черновик: `python3 tools/obmer_import.py <обмер.pdf|dxf> --out objects/<шифр>` → `obmer_draft.py`, `preview.png`,
  `texts.json` (размерные тексты). Стены — по двойным линиям, помещения — заливкой (площади ±1–7 %; балкон/лоджия
  и тонкие перегородки часто теряются). Черновик — НЕ результат: довести по цепочкам размеров до точного `obmer.py`.
- Растр/скан — вручную по цепочкам размеров. Сверить сумму цепочек с габаритом.
- Выбрать систему координат: длинная сторона квартиры — по y (вправо по листу), x — вниз; начало — угол.
- `WALLS` прямоугольниками, `ROOMS` контурами по граням, `SHAFT`, существующие `DOORS`. Окна — в `design.WINDOWS`.
- Собрать только лист обмера: `python3 build.py objects/<шифр> obm` → открыть preview.pdf, сверить с исходником
  (все размеры, площади помещений). Расхождения > 20 мм — исправить; неизвестное — «уточнить по месту».
- Чего не хватает (высоты, стояки, щит…) — список вопросов (в конец, в `texts.CHECKS`).

## 2. Планировочное решение и экспликация → design.ROOM
- Сценарии жизни + референсы → функциональное зонирование; мокрые зоны — у стояков (кухня дальше 3–4 м от
  стояка → КНС или подиум; санузел над жилыми у соседей — нельзя, ПП № 47 п. 24).
- Нормы проходов: проходы ≥ 700 (лучше 800–900), у кровати ≥ 600, перед унитазом ≥ 600, от оси унитаза
  до препятствия ≥ 300 (лучше 350–400), перед раковиной ≥ 700, между рядами кухни ≥ 1000–1200.
- `ROOM`: названия, отметки полов (±0,000 — чистый пол жилых; санузлы +0,000…+0,020), потолки, коды покрытий,
  zone, ceil_code, plinth. Экспликация считается автоматически (площадь — по контурам, до 0,1 м²).

## 3. Параметры помещений → design.py (+ annot/texts/album)
Порядок заполнения: двери и типы → мебель (`ITEMS`) → отделка (`FINISH`, `WALL_ZONES`, `WALL_DEFAULT`,
`TILE_LAYOUT`, `FLOOR_TILES`) → свет (`LIGHTS`, `GROUPS`) → выключатели и розетки (`POINTS`) → сантехника
(`PLUMB`, `RISERS`, трассы) → тёплые полы (`HEAT`) → потолки (`CEIL_FEATURES`) → вентиляция (`VENT`).
Правила бюро:
- Высоты по умолчанию: розетки +300, у столешницы +1100, у кровати +650, выключатели +900 везде, столешница +900,
  раковина +850, низ полотенцесушителя ≥ +600 над полом; терморегуляторы +900.
- От края проёма до оси первого выключателя ≥ 100 мм (в проекте 150); выключатели — со стороны ручки,
  не за полотном; изделия на одной высоте — в общих рамках (шаг 71).
- Розетки в санузлах — IP44, вне зон 0–2 (≥ 1,2 м от лейки / 0,6 м от стекла), линии через УЗО 30 мА.
- Тёплый пол — не под мебелью без ножек, сантехникой, коробами (расчёт маски автоматический).
- Плитка — от осей (раковина, унитаз, проём, центр стены), подрезка ≥ 1/2 плитки на видимых углах.
- Встроенная мебель до потолка: потолок примыкает, окраска за ней не считается (полоса 150 по кромкам).
- Двери одного размера и работы — один тип с количеством.
- Сгенерировать файлы параметров: `python3 build.py objects/<шифр> --params` → `out/params/*.md`.

## 4. Сквозная проверка
- `python3 tools/check.py objects/<шифр>` → `out/check.md`. Все E (ошибки) — исправить в данных.
  W (предупреждения) — решить; что остаётся (уточнения, согласования) — в `texts.CHECKS` с вариантами решения.
- Дополнительно глазами: открывание дверей и мебель, свет над столом/островом по оси, ТВ не против окна,
  кондиционер не над кроватью/столом, радиаторы не закрыты, вытяжка над варочной, розетки у всех потребителей.

## 5. Выпуск
- `python3 build.py objects/<шифр> all` (+ `--dxf` по запросу) → `tools/cover.py objects/<шифр> N`.
- Оформление планов (annot.py): собрать отдельные листы (`build.py … fur,flr,lgt`), посмотреть PNG
  (`pdftoppm -r 70`), поправить положения бирок/подписей/цепочек, пока ничего не перекрывается.
- Развёртки: по умолчанию авто-компоновка; для сложных помещений — свои листы в `album.py` (образец — эталон).
- Визуализации: панорамы 360° в `photos/src_<пом>.jpg` — фото/рендеры заказчика или свои:
  `tools/model3d.py objects/<шифр> pbrt` → `pano 03 04…` (нужны pbrt-v4 и OIDN: `engine/ifc/pbrt/setup_tools.sh`,
  ~20–40 мин на помещение). Без панорам титул строится с планом, листы визуализаций не выпускаются.
  Виды и полосы титула — в `vizcfg.py` (без него — авто-камеры).
- 3D-модель по запросу: `tools/model3d.py objects/<шифр> ifc` и `pack` (zip с IFC/GLB/OBJ и контрольными видами).

## 6. Самопроверка (обязательно перед отдачей)
- Открыть PDF, просмотреть КАЖДЫЙ лист (растр 60–70 dpi, ключевые — 120 dpi): нет наложений текста, всё в рамке,
  штамп заполнен, номера листов = ведомость, позиции = спецификации, размеры между планами совпадают.
- `tools/check.py` — 0 ошибок. Итог пользователю: файл, 2–3 строки о решениях, единый список вопросов.
- Выложить в знания проекта: `claude/00-obshchee.md`, `claude/NN-<помещение>-parametry.md` (из out/params).

## Известные ошибки прошлых объектов (не повторять)
- Тумба перед унитазом — сесть невозможно (ДП-01, ред. 4): проверять зону 600 перед унитазом и 300 от оси.
- Бра/подсветка над подушкой в детской — не делать без запроса.
- Выключатель 75 мм от проёма — недопустимо (коробка ~100 мм).
- Кухня далеко от стояка: самотёк 2 % в стяжке не проходит → КНС, напорная линия; вытяжка — рециркуляция.
- Окраска/обои за встроенной мебелью не считаются (только 150 мм по кромкам).
- На плане мебели без номеров позиций; техника — словами; на плане потолков — без светильников.
