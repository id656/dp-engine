# dp-engine + PORTFOLIO Студия

**Установка на Windows одним файлом:** скачайте [`PortfolioStudio-Setup.cmd`](PortfolioStudio-Setup.cmd) и запустите.
Он поставит Git, Python и Claude Code, если их нет. Затем клонирует этот репозиторий в `%LOCALAPPDATA%\PortfolioStudio\dp-engine`
и поставит пакеты движка, навык «dizain-proekt-kvartiry» и ярлык «PORTFOLIO Студия». В конце откроет вход в Claude.
Повторный запуск установщика обновляет всё. Приложение само делает `git pull` движка при каждом старте.

**PORTFOLIO Студия** (`studio/`) — приложение с тремя режимами:
- IFC из планов и визуализаций;
- альбом из IFC;
- дизайн-проект из планов и референсов.

Каждый запрос — новая сессия Claude (Claude Code без окна, вход вашей подпиской) в отдельной папке задания
с копией движка. На компьютер возвращается только `РЕЗУЛЬТАТ` и `ОТЧЁТ.md`.
Оформление — как у веб-просмотрщика бюро: глубокий синий, тёплый белый, латунь; шрифты Prata, PT Sans Narrow, PT Mono
(OFL, `studio/fonts`).

# dp-engine — движок рабочих чертежей дизайн-проекта квартиры

Один набор данных об объекте → весь альбом А3 (PDF, по запросу DXF R12), файлы параметров помещений (md),
листы визуализаций, при необходимости IFC-модель и 360°-панорамы. Оформление — по стандартам бюро
(штамп 185×30 с логотипом PORTFOLIO, титул с четырьмя полосами фото, цветные планы).

Эталонный объект — `objects/dp-01-2026-ai` (квартира 53,2 м², г. Санкт-Петербург, ред. 5).
Тестовый/шаблонный объект — `objects/_template` (квартира 52 м² без оформления: проверка автоматики движка).

## Быстрый старт

```bash
pip install reportlab numpy scipy pillow pypdf --break-system-packages   # если чего-то нет
python3 build.py objects/dp-01-2026-ai all            # альбом -> objects/<объект>/out/<шифр>_Рабочая_документация.pdf
python3 build.py objects/dp-01-2026-ai all --dxf      # + DXF R12 по листам (zip)
python3 build.py objects/dp-01-2026-ai fur,flr        # отдельные листы -> out/preview.pdf
python3 build.py objects/dp-01-2026-ai --list         # состав альбома (ключи листов)
python3 build.py objects/dp-01-2026-ai --params       # файлы параметров помещений -> out/params/*.md
python3 tools/cover.py objects/dp-01-2026-ai          # обложка (логотип на весь лист + пустой лист) + альбом -> _редN.pdf
python3 tools/check.py objects/dp-01-2026-ai          # автопроверки модели (проходы, двери, выключатели, IP, уклоны…)
python3 tools/obmer_import.py обмер.pdf --out objects/<шифр>   # черновик obmer.py из PDF/DXF обмера (+ preview.png)
python3 tools/model3d.py objects/<шифр> ifc|pack|pbrt|pano     # IFC4/GLB, контрольные виды, сцена pbrt, панорамы 360°
python3 tools/regress.py                               # эталон собирается без изменений (после правок движка)
```

Новый объект: `cp -r objects/_template objects/<шифр-в-нижнем-регистре>` и заполнить файлы данных
(порядок работы — `docs/workflow.md`, поля — `docs/data-schema.md`, что запросить у заказчика — `docs/checklist.md`).

  plans.py               листы-планы: обмер, демонтаж, монтаж, мебель, полы, тёплые полы, потолки, свет,

  tables.py              общие данные, дизайн-проект (цветной план), общие указания, ведомость отделки,

  floorplan.py           раскладка плитки пола мокрых зон

  obmer.py               обмер: стены, помещения, существующие двери, остекление, размеры обмерного плана

  album.py               состав альбома, компоновка развёрток, разрезы, раскладки пола, узлы
  vizcfg.py              визуализации: камеры панорам, виды, полосы титула
  photos/src_<пом>.jpg   панорамы 360° (2:1) — источник видов и полос титула
  out/                   результат сборки (PDF, DXF, params, текстуры, виды)
docs/                    workflow.md, data-schema.md, checklist.md, instrukcii-proekta.md (инструкции проекта claude.ai),

tools/                   obmer_import.py (оцифровка обмера), check.py (автопроверки), cover.py (обложка),

Модули объекта подключаются по имени (`import design`, `annot`, `album`…): сборщик ставит папку объекта первой
в `sys.path`. Движок обращается к данным только через `model.py`; чего нет в данных — строит по умолчанию:

| Нет в данных | Что делает движок |
|---|---|
| `annot.PLAN_VIEW` | вписывает план в поле листа, масштаб 1:50 (1:75 / 1:100, если не помещается) |
| `annot.TAGS` | бирки помещений — в точке, наиболее удалённой от стен |
| `obmer.OUTER_DIMS / INNER_DIMS` | цепочки по стенам и проёмам сверху/слева, габариты помещений |
| `obmer.GLAZING` | окна по `design.OPENINGS` / `WINDOWS` |
| `design.OPENINGS` | проёмы из дверей (разрывы стен у петли) и окон |
| `design.RWALLS` | стены развёрток А, Б, В… по часовой от стены со входной дверью |
| `design.MATERIALS` | тип фактуры и запас — по тексту кода отделки (доска, керамогранит, окраска, мрамор…) |
| `album.sheets()` | типовой состав: общие листы, все планы и спецификации, авто-развёртки всех помещений, узлы |
| `vizcfg` / фото | титул с цветным планом вместо фото, листы визуализаций не включаются |
| пороги, отметки, марки дверей, силовые выводы | из модели (дверные проёмы между разными покрытиями, уровни полов…) |

## Соглашения

- Размеры — мм, отметки — м от ±0,000 (чистый пол жилых помещений); z в данных — мм от ±0,000.
- План на листе: **+y модели — вправо, +x модели — вниз** (поворот на 90° по часовой). Оцифровывать обмер так:
  x — вниз от верхнего края плана, y — вправо от левого. Длинную сторону квартиры — по y.
- Стены развёрток: А, Б, В… по часовой от входа; «от левого края» — при взгляде изнутри на стену.
- Коды отделки: П — полы, С — стены, Пт — потолки, ПЛ — плинтус; группы света — «номер помещения + буква» (3Д).
- Источник правды — `design.py` (+ `obmer.py`). Файлы параметров `NN-<помещение>-parametry.md` генерируются
  из модели (`--params`) и выкладываются в знания проекта как читаемая копия решений.

## Проверка, что движок не сломан

`python3 tools/regress.py` — собирает эталонный объект и сравнивает содержимое всех листов со снимком
`tools/baseline_dp-01-2026-ai.pkl` (поэлементно). После правок движка расхождений быть не должно,
если правка не касалась эталона намеренно (тогда обновить снимок: `--update`).

## 3D и панорамы

`engine/ifc/` — IFC4 (без внешних библиотек), текстурированный OBJ/glTF-просмотр, экспорт сцены в pbrt-v4
и стерео-панорамы 360° (ODS) с шумоподавлением OIDN. Внешние инструменты: `engine/ifc/pbrt/setup_tools.sh`
(клонирует pbrt-v4 с GitHub, накладывает патч ODS-камеры, собирает; скачивает OIDN). Сцена (`scene3d.py`)
строится из той же модели; см. `engine/ifc/README.md` об ограничениях.
